What does this do?

A let … in query is fine for a one-off transformation. A documented M function is better when you need to reuse the same logic with different inputs: callers get named parameters, type checks, and descriptions in Power Query invoke dialog.

Building that wrapper by hand is hard. This tool does the scaffolding for you: fill in the form (or import an existing function), then copy the generated M into Excel or Power BI.

Okay, so Power Query is the data-cleaning bit of Excel and Power BI. You write a let … in block that does something useful. To share it as a proper function, you need parameter names, types, docs the UI can show, and usually Value.ReplaceType. This page builds that wrapper for you. Fill the form on the left (ish). Copy the M on the bottom. Paste it into Power Query. That's the whole trick.
